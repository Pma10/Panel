# Panel · Go 구조 및 유지보수 가이드

[← README](../README.md) · [첫 서버 시작](getting-started.md) · [운영 및 배포](go-backend.md) · [기여 가이드](../CONTRIBUTING.md)

## 기본 원칙

- **하나의 Go 실행 파일:** 웹 UI는 `go:embed`로 포함합니다. 상시 Node.js·데이터베이스는 필요하지 않습니다.
- **표준 라이브러리 우선:** 비동기 로그와 파일 업로드는 스트림 방식, 설정은 소규모 JSON 파일에 원자적으로 기록합니다.
- **검증 전 자동 변경 금지:** 임의의 URL을 받아 Java를 설치하지 않고, PaperMC Fill v3의 공식 안정 빌드와 SHA-256만 허용합니다.
- **사용자 데이터 보존 우선:** 패널 실행 파일과 서버 월드·설정·백업 경로는 분리합니다. 서버 JAR 교체는 중지된 경우에만 수행합니다.

## 모듈 경계

| 파일 | 책임 |
|---|---|
| `go_main.go` | 환경 설정 검증, 단일 실행 파일 진입점, 시그널·HTTP 종료 |
| `go_manager.go` | 관리 서버 상태, Java 프로세스, 고정 크기 로그 순환 버퍼 |

| `src/i18n.js`, `src/i18n-en.js` | 화면 번역: 한국어 원문을 사전·패턴으로 바꿈. 새 언어는 사전 파일 하나 추가 |
| `go_java.go` | 설치된 Java 검색, 실행 명령어 템플릿 해석 |
| `go_files.go` | 서버 디렉터리에 한정된 파일 스트리밍·업로드 |
| `go_templates.go` | 공식 Paper/Folia 안정 JAR, 무결성 확인, 이전 버전 복구 |
| `go_backups.go` | 일관성 있는 정지 상태 백업·복원 및 예약 작업 정의 |
| `go_scheduler.go` | 최대 2개 동시 예약 작업자, 128개 작업 대기열 |
| `go_metrics.go` | Minecraft 상태 핑과 Linux Java RSS |
| `go_diagnostics.go` | 요청할 때만 읽는 Go 힙·RSS·GC 진단 |
| `go_resume.go` | 정상 패널 재시작 후 원래 실행 중이던 서버만 복구 |

## RAM과 처리량

- 로그는 **서버당 400개 × 최대 2,048자**, 고정 크기 순환 버퍼를 사용합니다. 실제 최대 메모리는 Go 문자열/객체 오버헤드에 따라 달라지므로 별도 계측이 필요합니다.
- 콘솔 UI는 최신 120행만 렌더링합니다. SSE 구독은 서버당 32개로 제한하고 느린 연결은 종료합니다.
- 예약 작업은 2개 워커로 제한합니다. 작업 대기열 128개가 가득 차면 무한히 쌓지 않고 로그로 실패를 남깁니다.
- Go 런타임은 `GOMEMLIMIT`를 선택적으로 지원합니다. **소프트 한도**이며 Java 프로세스 메모리와 다릅니다.
- 실제 프로세스 RSS와 GC 상태는 관리자 설정 메뉴에서 조회할 수 있습니다. 운영 중 자동으로 매초 수집하지 않습니다.

## 배포, 업데이트 및 복구

1. 소스에서 검사·빌드: `bash scripts/build-install-linux.sh`
2. 릴리스가 실제 존재할 때만: `sudo bash scripts/pconnctl-linux.sh update vX.Y.Z`
3. 새 바이너리의 SHA-256과 버전 확인 후 기존 바이너리 보관
4. 기존 패널 정상 종료 → 실행 중인 Java 서버 목록 보존
5. 새 패널 기동 → 로컬 인증 API 확인 → 이전 실행 서버 순차 재기동
6. 새 패널 기동 실패 시 바이너리 롤백; 월드 데이터는 그대로 유지

**실제 장애 복구에서 중요한 한계:** 재시작 직후 JVM이 완전히 시작됐는지까지 HTTP 패널 상태 검사로 보장하지는 않습니다. 관리자 화면에서 개별 서버의 상태·로그를 다시 확인해야 합니다. 강제 전원 차단 후 자동 복원도 아직 보장하지 않습니다.

## 테스트 순서

```bash
go vet ./...
go test -count=1 ./...
go test -race -count=1 ./...
go build -trimpath -o pconn .
bash scripts/verify-go.sh
```

코드·테스트 파일을 추가한 사실은 실행 성공을 의미하지 않습니다. GitHub Actions가 실제 테스트 단계를 수행하고 종료 상태가 성공일 때만 **CI 통과**로 기록합니다. 운영 변경 전에는 별도의 테스트용 Paper 또는 Leaf 서버에서 시작·종료·업데이트·백업·복원·로그·인증을 반드시 검증합니다.

## 신뢰 경계

현재 Java 서버는 패널 OS 계정으로 실행되며 **Docker/Wings 같은 서버별 격리가 없습니다.** 신뢰할 수 없는 JAR 또는 플러그인을 여러 사용자가 공유하는 호스트에서 실행하지 마세요. 이 구조의 목표는 본인이 관리하는 신뢰 가능한 단일 호스트 PvP 서버입니다.


## 종료·복원 경계에 관한 구현 주의사항

- 패널이 종료 시그널을 받으면 **관리 JVM 종료 후 HTTP 리스너 종료까지 기다린 뒤** Go 프로세스를 종료합니다. 이전에 수동 중지 요청이 있었던 서버는 재시작 목록에 포함하지 않습니다.
- Minecraft 상태 핑은 `starting → running` 전환에만 사용하며, 이미 `stopping`인 서버의 상태를 되돌리지 않습니다.
- Java stdout/stderr는 **2KiB 미만 고정 버퍼**의 스트리밍 로거로 처리합니다. `exec.Cmd.WaitDelay`를 통해 자식 프로세스가 파이프를 상속해도 종료 대기가 무제한 지속되지 않도록 제한합니다.
- 백업 복원은 백업의 서버 ID와 메타데이터를 확인하고, 임시 복사 결과의 **총 바이트 수와 파일 수**가 기록과 일치해야 현재 월드 폴더를 교체합니다. 동일 크기의 데이터가 변조됐는지는 이 검사만으로 확인할 수 없습니다.
- Paper/Folia 자동 설치는 버전 목록을 정렬한 뒤 상위 버전을 노출하고, 안정 빌드 중 가장 높은 빌드 번호를 선택합니다. 업데이트의 버전 정보가 저장되기 전까지 이전 JAR을 삭제하지 않습니다.

### 검증 수준

**로컬에서 단독 실행한 검증:** `boundedConsoleWriter`의 대용량 로그·부분 로그 처리와 Go `exec.Cmd.WaitDelay` 동작에 관한 격리 테스트 **3건이 `go test -race`를 통과**했습니다. 해당 격리 검사는 전체 Panel 코드베이스를 빌드하거나 실제 Minecraft JAR을 실행한 통합 테스트가 아닙니다.

**미완료:** 전체 Go 백엔드 `go build` / `go test -race ./...` 성공 확인, GitHub Actions 정상 실행, 실제 Paper/Leaf 실서버 종료·백업·복원 검증. 이 항목을 통과하기 전에는 운영 서버로 전환하지 마세요.
